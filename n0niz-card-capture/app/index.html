Card Capture

Turns card payment notifications into Firefly III transactions

Received notifications

How it works

Every time you pay with a card, its app shows a notification such as “You paid €12.34 at REWE”. An automation app on the Android phone forwards that notification here. Card Capture reads amount and merchant and books the payment into Firefly III, into that card's own account. Your Firefly rules then sort it into categories like any other transaction. Each card has its own address, so several cards and several phones work side by side.

This works on Android only. iPhones don't let apps read other apps' notifications.

  1. Connect Firefly III

    Open the Settings tab, paste your Firefly personal access token (the same one your scheduler uses) and save. Add the card there if it isn't listed yet. Card Capture checks the connection and creates the account … in Firefly if it doesn't exist yet.

  2. Keep Tailscale on, on your phone

    The phone has to reach the Umbrel when a payment happens, also when you're out. For a second person's phone, invite that phone to your Tailscale network (Tailscale admin → Share the umbrel machine, or add the device to your account).
    • Install Tailscale from the Play Store and log in with the same account as on your Umbrel.
    • Android Settings → Network → VPN → gear icon next to Tailscale → turn on Always-on VPN.
    • In the Tailscale app, make sure Use Tailscale DNS is on.

  3. Install MacroDroid

    Install MacroDroid from the Play Store (the free version allows enough macros for this). Open it once and allow notification access when asked. Also set MacroDroid to Unrestricted under Android Settings → Apps → MacroDroid → Battery, so Android doesn't put it to sleep.

  4. Create the macro: trigger

    • MacroDroid → Add macro, name it Card to Firefly. One macro per card.
    • Triggers → + → Device events → Notification → Notification received.
    • Select application(s): the card's app, and Google Wallet (it may appear as Google Services) if the card is used for phone payments. If every card has its last 4 digits set in Settings, one macro with all these apps is enough: notifications that name a card number go to the right card automatically, and the same payment reported by two apps is booked only once.
    • Text content: Any.

  5. Create the macro: action

    • Actions → + → Web interactions → HTTP request.
    • Method: POST.
    • URL: copy this. It contains your secret key, so don't share it.
      …
      Quick check: open … in your phone's browser with Tailscale on. You should see {"error": "wrong key"}. That means the phone reaches Card Capture. If you see the Umbrel login page instead, see “Troubleshooting” below.
    • Content type / body: choose application/json and paste this body:
      {"title":"{not_title}","text":"{notification}","app":"{not_app_name}"}
      The parts in curly braces are MacroDroid placeholders for the notification's title, text and app. If your MacroDroid version names them differently, insert them with the … (magic text) button next to the body field instead.
    • Save the action and the macro.

  6. Test it

    • Paste the text of a real Krak payment notification into the test box below to see what Card Capture would book.
    • Then make a small card payment. Within seconds it should appear in the Activity tab as booked, and in Firefly under the … account.
    • In MacroDroid you can also open the macro → ⋮ → Test actions; that sends empty placeholders, which shows up here as ignored. That's fine, it only proves the connection works.

  7. Let Firefly categorise

    The merchant becomes the description and the expense account of each transaction. Create rules in Firefly as usual, e.g. description contains “REWE” → category Groceries. Card Capture asks Firefly to apply rules on every booking. Every booking also gets the card's tag, e.g. ….

  8. Book top-ups as transfers

    When you pay the card from a bank account (a top-up, or the monthly credit card bill), create a Firefly rule that turns that payment into a transfer to the card's account. Otherwise the bill and the purchases are both counted as spending. If you also import the same card from a CSV statement, stop that, or every purchase appears twice.

Good to know

  • Needs review: notifications where no safe booking was possible, e.g. payments in a foreign currency (enter the € amount) or text the parser didn't understand. Fix them in the Activity tab.
  • Duplicates: Android sometimes shows the same notification twice; identical notifications within 15 minutes are ignored.
  • Missed payments: if the phone was off, Tailscale disconnected or notifications were silenced, a payment can be missing. Compare with the Krak app now and then.
  • Troubleshooting – Umbrel login page instead of the app: the receiving address is meant to bypass Umbrel's login (it is protected by your secret key instead). If your umbrelOS version still asks for a login, MacroDroid can't get through. Tell Claude what you see; the fix is one line in the app's settings file.
  • MacroDroid shows an error: in MacroDroid open the macro's log (⋮ → System log). “Unable to resolve host” means Tailscale was off or the address is wrong.
  • Paying from crypto: if the card spends a crypto balance, each payment is also a crypto sale, which can be taxable in Germany if held under a year. Card Capture only books the euro amount.
