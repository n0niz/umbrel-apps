Saving, not spending

Bookings in these categories (e.g. BTC purchases) are shown as saved and invested, not as expenses or income.

Kraken (for the Bitcoin page)

Use a read-only key with only Query Funds and Query Ledger Entries. The key from your Kraken importer works.

Krak cashback in Firefly

Books every cashback transfer from the Krak card to Kraken (found in the Kraken ledger with the key above) as a deposit “Krak cashback” in Firefly: the euro value of that day, the BTC amount in the note, each one only once. Choose a BTC account (e.g. “Kraken BTC”): it gets the sats as amount and the euro value as foreign amount, so your euro Kraken account stays right. Your Firefly rules run on it, so category and tags come from there. Runs after every Kraken sync.
After every Kraken sync its opening balance is set so the account shows exactly the BTC you hold on Kraken (bought and cashback). Not counted as income or spending.

Strike

Create an API key in the Strike Dashboard with only the scope partner.balances.read. Its BTC balance shows on the Bitcoin page and can keep a BTC account in Firefly at the right amount (only its opening balance moves, nothing counts as income or spending).

Bitcoin wallets watch-only

Paste an xpub / ypub / zpub, or for multisig the wallet's output descriptor (Sparrow: Settings → Script Policy → Export or Show descriptor). It can only read, never spend. Addresses are looked up in your own Mempool app.
